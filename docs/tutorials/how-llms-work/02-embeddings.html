Chapter 2

Giving numbers meaning

Token 4881 is just an arbitrary serial number — nothing about the digits "4881" tells you it means "France." The model's very first job is to turn that bare ID into something that actually carries meaning.

Analogy

Think of it like a fingerprint card. Every token ID gets looked up in a giant reference table and swapped for its own personal "fingerprint" — a long list of a few thousand numbers. This fingerprint isn't random: it was shaped, during training, so that tokens with related meanings end up with similar-looking fingerprints. The fingerprint for "France" will resemble the fingerprint for "Germany" or "Spain" far more than it resembles the fingerprint for "bicycle" — because the model noticed, across huge amounts of text, that country names get used in similar ways.

This fingerprint is called an embedding. It's what lets the model work with meaning instead of just arbitrary ID numbers — two different tokens that mean similar things start out numerically close to each other, which turns out to be exactly the kind of signal the rest of the model can build on.

In this project's GPT-2 implementation, each fingerprint has 768 numbers in it (bigger models use more — thousands, for the largest ones). The diagram above uses six bars purely so it fits on the page; the real thing is the same idea, just wider.

Numbers also need to know their place

There's a second problem to solve here. "The capital city of France is" and "France is of city the capital" use the exact same tokens — but obviously mean very different things. Fingerprints alone don't capture word order. So before the model does anything else, it also mixes in a signal for where each token sits in the sentence: 1st, 2nd, 3rd, and so on.

Analogy

Picture a seating chart at a dinner table. Knowing a guest's name (the fingerprint) isn't enough to understand the conversation — you also need to know where they're sitting relative to everyone else, because that affects who's talking to whom. Older models like GPT-2 use a fixed seating chart with numbered chairs — chair 1, chair 2, chair 3 … up to some maximum table size. Newer models use a cleverer trick called RoPE (short for Rotary Position Embedding) that works more like a compass bearing between guests than a fixed chair number — which, as it happens, is also the trick that lets some modern models handle enormous conversations (more on that in the bonus chapter).

Where we are so far

Our sentence has gone from plain English, to six token IDs (464, 3139, 1748, 286, 4881, 318), to six fingerprints-with-a-seat-number. The model hasn't "understood" anything yet — this is still just careful bookkeeping. The actual understanding happens in the next chapter.

Under the hood The fingerprint lookup table is the token embedding matrix loaded in purego/tensor/loader.go / generic_loader.go. GPT-2's fixed seating chart is its position-embedding table (PositionLearned in purego/tensor/config.go); the RoPE alternative used by Llama/Falcon/Granite lives in purego/tensor/rope.go.
