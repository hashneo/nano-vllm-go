Chapter 9

From GPT-2 to today: what actually changed

Every mechanic in Chapters 1–6 was taught using GPT-2, a real, small, 5-year-old model. This chapter is the history lesson: what OpenAI actually changed, release by release, to get from that same GPT-2 architecture to ChatGPT, GPT-4, and reasoning models like o1 — and, importantly, which of those changes you've already learned and which are genuinely new.

A note on this chapter Every other chapter in this tutorial is grounded in code you can actually run in this project. This one isn't, on purpose: GPT-3, ChatGPT, GPT-4, and o1 are closed, proprietary models with no public weights or source — nothing to point you at. What follows is public information about what changed, not this project's implementation of it. Chapter 10 comes back to real, runnable code — covering Llama, Falcon, and Granite, a separate, open lineage that evolved in parallel to the one below.

GPT-3 (2020): the exact same architecture, just much bigger

This is the easiest step to understand, because you already have the vocabulary for it: GPT-3 made no architectural change over GPT-2. It's the identical recipe from Chapters 1–6 — same attention, same residual stream, same next-token loop — just with both of Chapter 4's knobs turned way up. The largest GPT-3 model ("Davinci") used 96 layers and a hidden size of 12,288, for 175 billion parameters, compared to GPT-2 Small's 12 layers, 768 hidden size, and 124 million parameters. Context window also grew, from 1,024 tokens to 2,048.

A genuine surprise from pure scale

Simply making the same architecture bigger produced a real, unplanned side effect: few-shot learning. Show a large enough model a couple of examples of a new task directly in its prompt — no retraining, no fine-tuning, just examples in the text it's completing — and it gets noticeably better at that task. GPT-2 could barely do this; GPT-3 could do it well. Nobody explicitly designed this ability in; it "emerged" once the model got big enough, which is why it's called an emergent ability.

ChatGPT / GPT-3.5 (2022): teaching it to actually converse

You already know the first half of this story from Chapter 5: wrap the input in a chat template, then fine-tune the model on many examples in that shape so it learns to treat "complete this text" as "answer this question." That fine-tuning step has a name, Supervised Fine-Tuning (SFT), and ChatGPT adds a second phase on top of it that this tutorial hasn't covered yet: RLHF (Reinforcement Learning from Human Feedback).

Here's the idea: after SFT, humans are shown several different answers the model generated for the same prompt and asked to rank them, best to worst. Those rankings train a separate, smaller model — a reward model — whose only job is to look at an answer and predict how much a human would like it. Then the original model is adjusted, using that reward model as a scoring signal, to produce more answers that score highly and fewer that score poorly.

Analogy

SFT is like a student studying worked examples to learn the general shape of a good answer. RLHF is more like a student submitting several draft essays, having a teacher rank them best-to-worst without saying exactly why, and then revising future essays to chase whatever pattern seems to earn better rankings. It's a subtler, harder-to-specify kind of feedback than "here's the correct answer" — but it's remarkably effective at making a model's tone, helpfulness, and safety feel right.

GPT-4 (2023): bigger, multimodal, and probably many specialists

GPT-4's exact architecture was never published, but two things are known or strongly suspected, and you've already learned the mechanics of both from this project's own models:

  • Multimodal input — GPT-4 accepts images as well as text. This tutorial doesn't cover how (this project's models are text-only), but conceptually an image gets converted into its own set of "tokens" that join the text tokens in the same residual stream from Chapter 4.
  • Rumored Mixture-of-Experts — widely believed (never confirmed by OpenAI) to use the same panel-of-specialists idea Chapter 10 covers for Granite 3.0, just at a much larger, closed scale.

Context also grew again, to 8K tokens standard and 32K in an extended variant — the same context-window tradeoffs from Chapter 7, just with more memory budget thrown at the problem.

o1 and reasoning models (2024): the same loop, just longer

This is the one that sounds like a bigger leap than it actually is. Recall Chapter 5: decode is just repeated next-token guessing, over and over, until a stop token appears. A reasoning model like o1 doesn't change that loop at all — it just runs it for many more steps than usual on tokens you typically never see, working through intermediate "thinking out loud" reasoning before committing to the tokens shown as the final answer. It was specifically trained (extending the RLHF idea above) to be rewarded for working through good step-by-step reasoning paths, not just for the final answer's wording.

Analogy

Like the difference between blurting out the first answer that comes to mind versus working scratch-paper arithmetic before writing down a final number. Both are done by the same brain, using the same skills — one just spends more visible effort before answering. o1's "scratch paper" is a long run of ordinary decode steps you don't see, using nothing more exotic than Chapter 5's loop, run for longer.

GPT-5 and beyond: where the trends point

As of this writing, GPT-5 details are speculative. But the direction of travel across the whole industry (not just OpenAI) points squarely at techniques this tutorial already covers: longer context windows (Chapters 7 and 8's Mamba2 approach are exactly how some models get there affordably), more efficient attention (Chapter 10's GQA/MQA and FlashAttention), and sparser, MoE-style scaling (also Chapter 10).
