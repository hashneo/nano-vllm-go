Chapter 8

Mamba2: a running summary instead of a notebook

Chapter 6 left off on an uncomfortable fact: the KV cache's 144 index-card trays (for GPT-2 Small — more for bigger models) never shrink. Every token, forever, adds another card to every tray. Some of the newest models in this project's lineup — IBM's Granite 4.0 — solve this by ditching that approach entirely for most of their layers, using a different mechanism called Mamba2.

A notebook that gets overwritten, not appended to

A Mamba2 layer keeps something much smaller than a KV cache: one fixed-size running state per attention-style head. When a new token arrives, the layer doesn't file away a new card — it updates the existing state in place, blending the new token's information into the same fixed amount of storage that was already there. Whether the conversation is 10 tokens or 10,000 tokens long, a Mamba2 layer's memory footprint never changes size.

Analogy

A KV cache is a court stenographer, transcribing every single word verbatim — the transcript only ever gets longer. A Mamba2 layer is more like someone keeping a single running summary paragraph of a long meeting: after every new statement, they go back and lightly rewrite the same paragraph to fold the new point in, without the paragraph itself growing forever.

"Selective": learning how hard to overwrite

A plain running average would treat every token equally, which would let important early details get diluted away too quickly. Mamba2 avoids this with a learned, per-token dial called delta (written Δ) — essentially "how much should this specific new token overwrite what I already know, versus leave it alone?" A token carrying an important new fact can push Δ high and overwrite heavily; a filler word can push Δ low and leave the running state almost untouched. That per-token, learned adjustment is what the "selective" in "selective state-space model" refers to — it's not a fixed formula, it's something the model learned during training.

Before that update happens, each Mamba2 layer also takes a quick local glance backward — a few tokens' worth — through a small step called a causal convolution. Think of it as skimming the last handful of words before deciding how to revise the running summary, catching short, local patterns cheaply before the bigger state update happens.

Why this matters: cost that doesn't grow

Chapter 6 computed a real number: roughly 72 KB of KV cache per token for a small model — multiplied by every token, in every active conversation. A Mamba2 layer's cost per token, by contrast, doesn't multiply by conversation length at all — it's the same fixed amount of work and memory whether you're on token 10 or token 100,000. That's the real, practical payoff, and it's a big part of why Granite 4.0's larger model can advertise a 128,000 token context window without the same runaway memory cost a pure attention model of similar size would carry.

Real numbers from this project

Granite 4.0's smaller model keeps each Mamba2 layer's running state at a fixed 128 numbers per head, across 48 heads — set once in the model's configuration, and never resized no matter how long the conversation runs. Compare that to Chapter 6's KV cache, whose size is multiplied by however many tokens have been seen so far.

The catch — and why Granite still keeps some attention

Compressing everything into one fixed-size running summary has an obvious cost: unlike a full transcript, it can lose precise details from far back in a long conversation, especially exact wording rather than general gist. This is exactly why Granite 4.0 is a hybrid: its smaller model mixes in just 4 ordinary attention-plus-KV-cache layers among 28 Mamba2 layers (at specific positions in the stack), giving the model a few chances to consult something closer to a full, precise transcript, while still doing the vast majority of its work in the cheap, constant-cost Mamba2 layers.

Analogy

Like a team that mostly works from a running summary of a long project, but pulls up the full unabridged meeting transcript for a few specifically important checkpoints. Most of the time the summary is good enough and far cheaper to maintain; occasionally, precision matters enough to pay for the full record.

Under the hood The Mamba2 layer — its causal convolution, the Δ ("delta") projection, and the state update — is Mamba2Layer in purego/tensor/mamba2.go. Which layers are attention vs. Mamba2 is set per-model in ModelConfig.HybridLayers (purego/tensor/config.go, see NewGraniteConfig() for the real 4-attention/28-Mamba2 split), and the per-layer dispatch between the two happens in GenericBlock.Forward() in purego/tensor/generic_model.go.
